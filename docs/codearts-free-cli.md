# 本机 CodeArts 专属福利入口

2026-10-18 已用本机 CodeArts 26.9.26 完成两次真实福利请求：最小连通请求得到
`FREE_BENEFIT_OK`，随后生成三处文档修正。二者均指定
`benefit-model/glm-5.3-flash` 和 `maas_type: benefit`，未购买套餐、未切换普通模型。
真实回执与职责归属见 [使用证据](codearts-evidence.md)。

## 为什么领了 1000 万仍不能直接用普通 CLI

[官方福利说明](https://support.huaweicloud.com/offers-codeartsagent/codeartsagent_offers_0001.html)
（本次核对页面更新日期为 2026-10-16）说明：

- 每人每日可领取 1000 万 Token，当日 24:00 清零，不累计到次日。
- 福利只适用于指定模型，和普通套餐积分不互通。当前包含 `glm-5.3-flash`、
  `deepseek-v4.1-flash`、`deepseek-v4-flash-0731`、`deepseek-v4-pro-0813`。
- 官方提供的领取／使用步骤覆盖 IDE、插件、桌面、网页、小程序：登录领取，再选择活动模型。
  页面没有单列 CLI 福利操作步骤。

本机普通 `codearts models` 当前返回五个普通模型，没有 `benefit-model/*`；
列表中的 `glm-5.3` 和福利 `glm-5.3-flash` 不是同一个调用目标。
本机 26.9.26 启动器的普通入口未进入福利模型加载分支，原生 `run` 还需要明确的福利请求头。
所以凭据存在、普通列表能显示、领取过福利，这三项不能证明普通推理请求走了福利额度。

本项目使用进程级原生内核集成参数完成验证，没有修改官方启动器或用户永久配置。
**这是本机版本验证过的适配方式，不是华为公开承诺支持的 CLI 免费版教程。**
不是通过购买套餐解决，也不把福利当作业务 MaaS API 的免费额度。

## 现在怎么用

已有 CodeArts 安装及本机 CLI 凭据的这台 Ubuntu，从仓库根目录执行：

```bash
# 极小真实请求；成功会输出 FREE_BENEFIT_OK。
bash tools/codearts-free.sh --probe

# 直接问答或要求生成补丁文本。
bash tools/codearts-free.sh "请简要解释这个项目如何区分仿真录像与实机照片。" --file README.md

# 明确选择要提供的公开文本；不自动上传整个仓库。
bash tools/codearts-free.sh "检查这份说明中的过时描述，给出修改建议。" \
  --file .codeartsdoer/README.md --file docs/codearts-evidence.md
```

命令依赖系统已有 Python 3.10+ 和用户现有的 `CODEARTS_CLI_AK`、`CODEARTS_CLI_SK`，
不要求启动后端、安装新环境或购买服务。已有凭据不要重新贴进聊天。
其他机器先按 [官方 CLI 授权说明](https://support.huaweicloud.com/usermanual-cli/codeartsagent_cli_0026.html)
自行完成本人授权；本工具不生成、保存或代为申请密钥。

这个入口固定使用已验证的专属福利模型，同时将辅助模型设为同一福利模型，
没有可切换普通模型的参数或失败后自动切换逻辑。工具执行权限设为 deny，
用于问答、审查和生成补丁；它不会直接修改业务文件或执行构建。
例如本次文档补丁由 CodeArts 生成，再由 Codex 核对并应用。
普通的 `codearts` 命令保持原样，暂不把它等同于这个专属入口。

对本次实际测试过的原生二进制做 SHA256 校验；版本变化会先拒绝，
需要重新核实福利路由后才能更新记录。工具不会自动安装或升级 CodeArts。
未修改永久配置，不继承启动器禁用 TLS 校验的选项。

每次在 `.local/codearts/free-cli/<UTC时间>-<随机标识>/` 保存：

| 文件 | 内容 |
| --- | --- |
| `request.md` / `sandbox/` | 实际请求与所选公开附件快照 |
| `events.jsonl` / `response.md` | 实际事件与模型原回答，经本机路径／已知凭据脱敏 |
| `receipt.json` | 模型、时间、退出码、事件数、Token 计数和文件哈希 |
| `stderr.txt` | 私有诊断日志，已知凭据脱敏 |

输出目录默认不入 Git；失败保留记录并以非零退出码结束。原生 CLI 即使退出 0，
只要没有回答或含错误事件，也不当作成功。不会据此改选普通模型。
CLI 事件的费用字段为 0 不等于账单证明；本轮没有查询账户余额或今日剩余福利额度。

## 日后额度或入口有变化

每天的福利独立计算。可以先通过官方支持的网页／IDE 等入口登录，确认当天福利已领取，
并检查所选模型属于活动范围，再用 `--probe` 验证本机调用。
领取规则及活动结束时间以官方最新通知为准，不承诺未来日期或其他版本同样可用。

如果出现福利不足、模型不可用、凭据失效或版本校验失败，保留本次错误记录进行核查。
不要因为普通 CLI 只显示其他模型就随意切过去；普通模型没有自动使用这份福利的承诺。
本工具也不订阅套餐、不创建云资源。业务视觉模型与云部署仍需分别准备。
